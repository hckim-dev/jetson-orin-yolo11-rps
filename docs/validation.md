## 게임 로직 회귀 검사

```bash
python3 -B -m unittest discover -s tests -v
```

표준 라이브러리만으로 실행하며, 대기 시간을 실제로 소비하지 않고 FSM의 시간을 제어합니다. 규칙의 전체 제스처 조합, 좌우 분할과 최고 신뢰도 선택, 최빈값의 미검출·동률 처리, 수동·자동 라운드 준비, 목표 점수 도달 후 종료, 초기화를 검사합니다.

라운드 전환의 회귀 검사는 다음 동작을 확인합니다.

- PvE Normal에서 수동·자동으로 새 라운드를 시작할 때마다 PC 패를 다시 선택합니다.
- 어느 플레이어가 목표 점수에 도달해도 결과 화면에서 SPACE를 누르면 매치 종료 상태로 전환합니다.
- 목표 점수에 도달한 매치는 결과 표시 시간이 지나면 자동으로 종료하며, 초기화 후 다시 시작할 수 있습니다.

이 테스트는 모델 탐지 품질이나 GPU 실행을 검증하지 않습니다.

## 동작상 제약

- 판정에는 최소 유효 검출 수가 없습니다. 적은 유효 관측으로도 패를 확정할 수 있습니다.
- God Mode의 카운터 생성은 프레임 단위입니다. 미검출이 섞인 최종 집계까지 항상 승리한다고 보장하지 않습니다.
- 후처리는 특정 모델 출력 형식과 클래스 순서를 가정하고, 클래스 구분 없는 NMS를 적용합니다.
- 카메라 속성 요청 결과를 검사하지 않으며 FPS 설정값은 캡처에 적용되지 않습니다.
- 엔진 입력 shape·dtype·입출력 개수의 명시적 사전 검증과 동적 shape 지원은 없습니다.

판정과 메모리 구조의 상세 내용은 [아키텍처](architecture.md), 엔진 준비 조건은 [실행 가이드](setup.md)를 참고하세요.

자격 증명과 보안 CI의 검사 범위는 [저장소 검사 안내](credential-security.md)에 정리했습니다.

## 성능을 기록할 때의 기준

HUD의 FPS는 루프 내 두 시점의 시간 간격에서 계산한 처리율의 지수이동평균입니다. 카메라 노출부터 디스플레이 표시 완료까지의 E2E 지연을 직접 측정하지 않습니다.

성능 수치를 추가할 때는 보드 모델, JetPack·CUDA·TensorRT·Python 버전, 전력·클록 모드, 카메라 실제 해상도·촬영 속도, 엔진 입출력·정밀도, 워밍업·측정 구간을 함께 기록해야 합니다. 추론 시간과 전체 루프 시간을 구분하고, 분포와 측정 코드·원시 로그를 함께 보관합니다. 정확도는 평가 데이터와 판정 기준을 명시한 별도 평가가 필요합니다.
